# ふりかえり将棋 — AIエージェントによる棋譜ふりかえり

KIF / CSA 棋譜をアップロードして、自分の感覚で手に印（6つのラベル）を付けると、将棋エンジン（[やねうら王](https://github.com/yaneurao/YaneuraOu)（[Wiki](https://github.com/yaneurao/YaneuraOu/wiki)） + 水匠5）が全手を解析し、
AIエージェント（Gemini + ADK）が**自分で勝負どころを選んで深く読み直し**、講評を書きます。
「15手目で３四飛ならどうだった？」と質問すると、エンジンで確かめてから答えます。
**ログイン**（利用者名とパスワード）してから使います。利用者は `python tools/add_user.py <利用者名>` で追加します
（公開しているサービスの利用者は `BUCKET=<バケット名>` を付けて実行）。保存するのはパスワードのハッシュ（scrypt）だけです。
同じ利用者名で5回続けて間違えると、5分間ログインできません。
ログイン画面の「新しい利用者を登録する」から、画面でも利用者を登録できます（パスワードは8文字以上。すでにある利用者名は使えません。
登録できる数には上限 `MAX_USERS`（既定30）があり、`SIGNUP_CODE` を設定すると登録に合言葉が要ります）。登録のときに生年月日も入力します（保存するのはハッシュだけ）。
パスワードを忘れたときは、ログイン画面の「パスワードを忘れた場合」で利用者名と生年月日が一致すれば、新しいパスワードに初期化できます
（同じ利用者名で5回続けて間違えると5分間止めます。生年月日を登録していない以前の利用者は、ログインしたあと左の欄の「生年月日を登録する」で、いまのパスワードを入れて登録できます）。
最初の画面の**保存した対局**から、保存に同意した対局の解析結果・印・AIエージェントとのやり取りをいつでも開き直せます
（解析はやり直しません。ふりかえりノートのPDFもそこからダウンロードできます。Cloud Storage では保存から30日で消えます）。
最初の画面には**これまでの記録**（保存に同意した対局の集計: 選んだ原因の回数、自分が指した手のうち悪手候補だった割合（100%なら全部の手、0%なら悪手候補なし）、
段階ごとの悪手候補の割合（序盤・中盤・終盤の順で固定）、悪手候補に自分で気づけた割合）が出ます。
集計は決まった規則で数えるだけで、AIエージェントは次のふりかえりでこの記録を道具（`past_tendencies`）から読みます。モデル自体の再学習はしていません。
最初の画面の「棋譜を入力する」ボタンから**棋譜入力モード**に入ります。棋譜入力モードでは、棋譜ファイル（.kif / .kifu / .csa / .txt）を読み込むか、将棋アプリでコピーした棋譜のテキストを貼り付けるか、
将棋盤の図（cshogi が描く盤）のマスを押して1手ずつ指して入力します（平手のみ。指せる手だけ入力でき、成る・成らないは選べます。持ち駒は盤の上下のボタンから打ちます）。
棋譜として読めないもの（指し手が無い、指せない手がある、400手を超える、200KBを超える、対応していない種類のファイル）は、
理由を示して受け付けません。KI2 形式（「▲７六歩 △３四歩」と並べた形）には対応していません。
棋譜入力モードとふりかえりは、いつでも行き来できます（付けた印と解析結果は残ります。別の棋譜を読み込むと消えます）。
**棋譜を読み込むと、エンジンの解析は裏で自動的に始まります**（結果は、印の入力を完了するまで表示しません）。
完了すると解析結果を表示し、AIエージェントのふりかえりも自動で始まります。「印を付けずに、すぐ解析結果を見る」を押せば、棋譜だけで解析まで進みます。
画面を閉じた後も処理が最後まで進むことは保証していません（Cloud Run が接続の無いあいだ CPU を絞るため）。
思考時間は数字で入力します（0、または100〜3000ミリ秒）。0 にするとエンジンで解析せず、印とコメントだけを記録します。
読み込んだ棋譜は、棋譜入力とふりかえりの両方の画面からダウンロードできます。
「次回からも確認せずに保存する」を入れると、保存の同意のチェックが次回から最初に入ります（外せば元に戻ります）。
「いったん閉じて、あとで印を付ける」で、棋譜を保存して解析を裏で進めたまま閉じ、あとで「保存した対局」の「続ける」から印を付けられます。
保存にチェックを入れずに始めると確認が出ます（保存しない／保存する／保存せず、以後ログアウトまで確認しない）。
保存しない場合も、解析のあいだは処理用のメモリで棋譜を扱い、AIエージェント（Gemini）には指し手とエンジンの数値を送ります。
解析結果の画面の「ふりかえりをやり直す」で印を付け直せます（解析結果を見たあとの印であることを、その対局に記録します）。
保存した対局は、最初の画面の一覧から削除できます（元に戻せません）。
盤面で入力したときは「投了」ボタンで、そこまでの棋譜でふりかえりを始めます。
**棋譜の保存は、本人が同意のチェックを入れたときだけ**行います（Cloud Storage の `games/<利用者>/`、30日で自動削除。対局者名を含む棋譜のまま保存します。
保存したものを画面から取り消す機能はありません）。保存先（`BUCKET`）が無い環境では手元の `data/` フォルダーに保存し、自動では削除しません。
AIエージェントへの依頼は裏で動かすので、待っているあいだに別の操作をしても、やり取りは消えません。質問と回答は、ふりかえりノートの末尾に入ります。
棋譜を入力するときに**自分が先手か後手か**を選び（必須。印を付ける画面でも直せます）、局面図を見ながら手に**印**を付けます（2026-10-14 に6つのラベルへ変更）。
選んだ手が自分の手か相手の手かで、選べるラベルが変わります:

| | 悪手 | 中間 | 好手 |
| --- | --- | --- | --- |
| 自分の手 | 悪手だと思った | ほかにも指す手があった | 好手だと思った |
| 相手の手 | 悪手だと思った | 予想外で驚いた | 好手だと思った |

原因（選択式）、コメント、迷った別の読みは、どのラベルでも任意です。上限はラベルごとに10個です。
**解析結果は、この入力を完了するまで表示しません**（答えを見ながらでは学習にならないため）。
完了すると、**ラベルごとのふりかえり**（6つのタブ）に、印を付けた手の局面、エンジンの判定、その後の読み筋（最善手から・実戦の手から）、
迷った読みの評価を並べ、AIエージェントの講評もラベルごとに書きます。「読み筋を盤で見る」を押すと、最善手からの読み筋と実戦の手からの読み筋を
ポップアップで開き、1手ずつ盤で確かめられます（局面図の下にもあります）。エンジンとの突き合わせは決まった規則で分けます:
- 悪手だと思った（自分の手・相手の手）: 一致（エンジンでも悪手・疑問手・緩手）／感覚だけ（勝率はほとんど下がっていない）／
  データだけ（エンジンでは悪手候補だが、印を付けていない。相手の手なら咎め損ねたかもしれない手）
- 好手だと思った（自分の手・相手の手）: 一致（エンジンの最善手と同じ）／感覚だけ（最善手とは違う）／データだけ（エンジンの**好手候補**で、印を付けていない）
- ほかにも指す手があった・予想外で驚いた: 区分は付けず、エンジンの判定（最善手と同じか、悪手候補か）と迷った読みの評価を並べます

好手候補は、最善手を指し、次善手なら勝率が10%以上低かった手です。しきい値は仮の値です。取り返すしかない局面の当然の手も入り、
思考時間が短いと結果が変わることがあります。以前の「悔しかった手」の印は、自分の手なら「悪手だと思った」、相手の手なら「予想外で驚いた」として読みます。
手は「初期盤面」から前後ボタンかキーボードの ← → で送り、局面図では選んだ手のマスに色が付きます。
入力途中の原因とコメントは、別の手に移っても残ります（ブラウザを再読み込みすると消えます）。
結果は**ふりかえりノート**（A4。ラベルごとの表、形勢グラフ、ラベルごとに印を付けた手と自分の悪手候補の局面図、AIエージェントの文章）として、
PDFでダウンロードするか、印刷用ページを新しいタブで開いて印刷できます。前半は「その手を指す直前の局面図」、
後ろのページは「回答」で、エンジンの最善手を指した局面図と、最善手・実戦の手それぞれの**その後の読み筋**（エンジンが短い時間で読んだ
想定手順、最大12手）を載せます（最善手は前半には書きません）。解析結果の画面の局面図の下にも、同じ読み筋を表示します。
解析結果の画面では、形勢グラフや表の行を押すと、その手の局面図を表示します。
PC の幅では、上段の左に形勢グラフと局面図、右にAIエージェントの講評を並べ、表はその下に置きます（スマホの幅では縦に並びます）。
講評の中の「15手目」などを押すと局面図がその手に移り、局面図で選んでいる手に触れている段落には色が付きます。
ダウンロードする棋譜のファイル名には、押した時刻を秒まで付けます（例: `kifu_20261014-153012.kif`）。
エンジンの読み筋が短く途切れたときは、終わりの局面を読み直して続きをつなげ、最大12手まで表示します
（局面図の下、ふりかえりノートの回答、迷った別の読みの「その先」、AIエージェントの講評）。

**迷った別の読み・大会に向けた傾向まとめ**（2026-10-14 追加）:
- 印を付けるときに、その手を指す直前の局面の盤で**迷った別の読み**を入れられます（1つの印に3つまで、1つの読みは6手まで。
  相手の応手も入れられ、成る・成らないも選べます）。評価は印の入力を完了した後で、エンジンが読みの1手ずつの最善手と判定、
  読みの終わりの勝率（実戦の手の後と比べて、5%以上の差で「良い／悪い」）、その先の読み筋を出します。ふりかえりノートの「回答」にも載ります。
- 局面図（画面・PDF・印刷用ページ）では、**成り駒を赤い字**で描きます。
- 対局を保存するたびに、最初の画面の**大会に向けた傾向まとめ**を裏で作り直します（A4で3ページ以内のPDFと印刷用ページ）。
  1ページ目は、決まった規則で数えた「記録から言えること」と、Gemini が書いた「AIの所感」（箇条書き）。
  AIの所感は、記録に無い数字を含む行・長すぎる行を取り除いてから載せます。2〜3ページ目は、規則で選んだ局面例（最大4つ。
  悪手だと思った自分の手、気づかなかった悪手候補、予想外で驚いた相手の手、迷った読みのほうが良かった手）の局面図です。
  集計が前回と同じなら作り直しません（Gemini を呼びません）。Gemini が使えないときは、記録と局面例だけで作ります。
  「迷った読みと実戦の差 5%」は仮の値です。

## 設計の考え方

- **将棋の判断はエンジン、言葉にするのは Gemini。** 指し手の良し悪し・勝率・読み筋はすべてエンジンの数値。
  Gemini はツールの結果だけを根拠に書くよう指示し、どの局面を調べるかを自分で決める。
- **エージェントの道具（`shogi_coach/tools.py`）**
  | ツール | 何をするか |
  | --- | --- |
  | `analyze_game` | 全手を短時間で解析し、形勢の推移と悪手候補・好手候補を返す |
  | `deep_dive(ply)` | 指定局面を2秒・候補手3つで読み直し、実戦の手と比べる（1回のふりかえりで最大6局面） |
  | `compare_move(ply, move)` | 別の手を指していたらどうだったかを比べる（日本語の指し手も可） |
  | `regret_gap` | 本人が付けた6つのラベルの印と、エンジンの判定とのずれを返す |
  | `past_tendencies` | 本人が保存に同意した、これまでの対局の集計を返す（今回の対局は含まない） |
- **印は本人が付ける。** エンジンやAIは代わりに付けない。ずれの区分は決まった規則（`shogi_analyzer/regret.py`）で分け、
  AIはその結果を文章にするだけ。コメントは命令ではなくデータとして扱うよう指示している。
- **セキュリティ**: エンジンAPIは非公開（IAM認証、web のサービスアカウントだけが呼べる）。Gemini は Vertex AI を
  サービスアカウントで呼び、APIキーを持たない。対局者名・棋譜コメントはモデルに送らない。入力は手数・サイズ・合法性を検査。
- **可観測性**: ツール呼び出しの開始・終了・所要時間・エラーを JSON で標準出力に出し、Cloud Logging で追える。
  画面にも「エージェントの行動ログ」を表示する。

## 構成

```
ブラウザ ─HTTPS→ Cloud Run: shogi-web（Streamlit + ADK エージェント）
                    ├─ Vertex AI: Gemini 3.8 Flash
                    ├─ Cloud Run: shogi-engine（FastAPI + やねうら王 + 水匠5, IAM認証）
                    └─ Cloud Storage（棋譜・結果, 30日で自動削除）
```

| パス | 内容 |
| --- | --- |
| `app.py` | Streamlit 画面 |
| `shogi_coach/` | ADK エージェント（`agent.py`）、ツール、エンジン呼び出し、保存 |
| `engine_service/` | shogi-engine（FastAPI）と Dockerfile |
| `shogi_analyzer/` | USI クライアント、棋譜読み込み、全手解析・深掘り・比較の共通処理 |
| `deploy/setup.sh`, `cloudbuild.yaml`, `web.Dockerfile` | Google Cloud へのデプロイ |
| `Dockerfile` | 1サービスにまとめた簡易版（エンジン同梱） |

## ローカルで動かす（Ubuntu 24.04 で確認）

```bash
# 1. エンジン（約1〜2分でビルド）と評価関数
git clone https://github.com/yaneurao/YaneuraOu.git
make -C YaneuraOu/source -j"$(nproc)" normal COMPILER=g++ TARGET_CPU=AVX2 YANEURAOU_EDITION=YANEURAOU_ENGINE_NNUE
mkdir -p engine/eval && cp YaneuraOu/source/YaneuraOu-by-gcc engine/YaneuraOu
curl -L -o Suisho5.7z https://github.com/yaneurao/YaneuraOu/releases/download/suisho5/Suisho5.7z
7z x -oengine/eval Suisho5.7z

# 2. Python
pip install -r requirements.txt -r engine_service/requirements.txt pytest

# 3. Vertex AI（AIエージェントを使う場合）
gcloud auth application-default login
export GOOGLE_CLOUD_PROJECT=<プロジェクトID>   # Cloud Shell では設定済み。Vertex AI・global は既定値

# 4a. 1プロセスで起動（エンジンも同じプロセス）
streamlit run app.py

# 4b. 本番と同じ2プロセス構成で起動
uvicorn engine_service.main:app --port 8081 &
ENGINE_URL=http://localhost:8081 streamlit run app.py
```

エージェント単体は `adk web` でも試せます（`shogi_coach` を選び、状態に棋譜を入れる必要あり）。

テスト: `python -m pytest tests`（エンジンAPI、Gemini の代わりに台本モデルを使ったエージェントの通し確認、
印とエンジン判定の突き合わせ、局面図、ふりかえりノートのPDF・印刷用ページ）

## Google Cloud へのデプロイ

```bash
export PROJECT_ID=<プロジェクトID>
bash deploy/setup.sh
```

API の有効化、サービスアカウントと最小権限、バケット（30日削除）、2イメージのビルド、2サービスのデプロイまで行います。
最後に予算アラートをコンソールで設定してください。

## 判定方法

評価値 cp を先手勝率 `1 / (1 + exp(-cp/600))` に変換し、指した側の勝率が
20%以上下がれば「悪手」、10%以上「疑問手」、5%以上「緩手」とします。
