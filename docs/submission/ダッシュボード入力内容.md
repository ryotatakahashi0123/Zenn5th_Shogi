```
**課題**

対象は、将棋アプリで指す初心者から初段前後の中級者です。上級者の振り返りにも使えます。
既存の解析サービスでも、評価値のグラフや悪手の一覧で「どこで形勢が傾いたか」は分かります。それでも、作者自身（将棋ウォーズ初段・将棋歴10年）の経験では、次の困りごとが残りました。

- 解析結果を見ても「ここが悪かった」と分かって終わり、次に何を直すかが決まらない。解析を使わず、人の指導だけで伸びた例もある
- 悔しかった手と、実際に形勢を壊した手がずれていても気づけない。気にしなくてよい手ばかり気にして、同じ間違いを繰り返す
- 悔しい手は「悩んだ末の手」か「手拍子の手」が多い。しかし、複数の対局をまたいで傾向を調べるのは難しい

**解決**

- **答えを見る前に、自分で印を付ける**: 局面図を見ながら、悔しかった手と好手に印を付けます。原因は「読み抜け」「焦り・早指し」など10種類から選びます。解析結果は、この入力を終えるまで見せません
- **ずれを見せる**: エンジンの全手解析と突き合わせ、決まった規則で「一致／感覚だけ／データだけ」に分けます
- **AIコーチが自分で調べる**: 本人の印と形勢の動きから局面を選び、エンジンで深く読んでから、ふりかえりを書きます。質問にも、エンジンで確かめてから答えます
- **手元に残す**: 局面図の問題と回答（最善手と読み筋）を、A4のノート（PDF）にまとめます
- **続けるほど傾向が分かる**: 同意した対局を保存し、選んだ原因や、悪手候補に自分で気づけた数を集計します。この集計は次のふりかえりに使います

棋譜を入れると、解析・ふりかえり・保存は裏で自動に進みます。勝率や悪手の判定はエンジンと決まった規則が出し、AIは数値を作りません。悔しさの印を付けるのは本人で、AIは代わりに付けません。
```

### アーキテクチャ説明（800字まで）

793字（改行・記号を含む）。

```
**構成**

- **Cloud Run「shogi-web」（公開）**: 画面（Streamlit）とAIコーチ（Agent Development Kit）を動かします。GeminiはVertex AIをサービスアカウントで呼ぶので、APIキーを持ちません
- **Cloud Run「shogi-engine」（非公開）**: やねうら王＋水匠5をFastAPIで提供します。IAM認証が必須で、shogi-webのサービスアカウントだけが呼べます
- **Cloud Storage**: 本人が同意した対局だけを利用者ごとに保存し、30日で自動削除します。パスワードは保存せず、scryptのハッシュだけを置きます
- **Cloud Logging**: エージェントが呼んだ道具の開始・終了・所要時間・エラーを記録します
- **Cloud Build**: 2つのサービスのイメージを作り、1本のスクリプトでデプロイします

**設計上の工夫**

- **数値はエンジン、言葉はGemini**: 評価値を勝率に直し、指した側の勝率が20%下がれば悪手、10%なら疑問手と規則で判定します。AIが決めるのは、調べる局面、使う道具、言葉づかいです
- **道具は許可リストで固定**: 全手の形勢、印とのずれ、過去の傾向、局面の深掘り（6局面まで）、手の比較（10回まで）の5つだけです。Web検索は持たせていません
- **本人の入力はデータとして扱う**: コメントを命令として扱わないよう指示し、対局者名はモデルに送りません
- **止まらない**: AIの呼び出しが失敗しても、エンジンの結果とずれの表は表示します
- **試験**: 突き合わせ・集計・ノート・棋譜の読み込みは画面から切り離した関数にし、GitHub Actionsで自動試験を回しています
```
