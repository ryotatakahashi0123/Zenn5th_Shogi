### 04 設計指示書

- **1. 最上位原則（7項目）は、いまも守っている。** 数値は規則とエンジンが出す、LLM の出力を信用しない、人の印を代筆しない、AI 所感とデータを分ける、失敗しても止まらない、最小の権限・保持、確認していないことを確認したように書かない
- 2. モジュール構成: `app/` ではなく、`app.py`（画面）、`shogi_analyzer/`（解析・突き合わせ・集計・ノート）、`shogi_coach/`（エージェント、保存、ログイン）、`engine_service/`
- 3. KIF 解析: cshogi で読む。貼り付けは内容から KIF / CSA を見分ける。KI2 は未対応
- 4. 時間分析: **未実装**
- 5. 評価値分析: 評価値 cp を勝率 `1/(1+exp(-cp/600))` に直し、指した側の勝率の下落が 20% で悪手、10% で疑問手、5% で緩手。好手候補は「最善手を指し、次善手との勝率の差が 10% 以上」（仮の値）
- 6. 突き合わせ: 4区分ではなく3区分（一致／感覚だけ／データだけ）。「時間の癖」は無い。好手にも同じ考え方の区分がある
- 7. エージェント: 03 の表のとおり。深掘りは6局面まで、比較は10回まで
- 8. 知識カード: 未実装
- 11. セキュリティ: エンジン API は IAM 認証で非公開。Gemini はサービスアカウントで呼ぶ。対局者名・棋譜コメントはモデルに送らない。ログインのパスワードは scrypt のハッシュだけを保存。保存は本人の同意があるときだけ
- 12. 可観測性: 道具の開始・終了・所要時間・エラーを JSON で標準出力に出す。画面に「エージェントの行動ログ」
- 13. コスト: 1日の上限（`DAILY_COST_CAP_USD`）の仕組みは無い。解析のたびに AIエージェントが自動で動くので、利用が増えると Gemini の費用も増える。利用者登録の上限（既定30人）と合言葉（`SIGNUP_CODE`、未設定）がある
